# Kiri Fitness 課程預訂系統 — 需求規格

> **版本**：v2.3（2026-09-12）
> **v1 → v2 的重大改變**：改採「電影場次 + 當月點數」模式，付款時點從「成班後結算」提前到「早鳥期購票」。差異詳見第 15 節。
> **v2.1 追加確認**：一期堂數可變；「認證學生」與「舊生」為同一概念；所有期程日期（上架、早鳥截止、最後確認日）由管理員自訂。
> **v2.2 結構調整**：改為**課程 / 場次兩層結構**。「課程」是學生瀏覽與購買的主體、票種掛在課程層級；「場次」是預約與成班的最小單位。狀態機因此拆為兩層。見第 4.1 節與第 8.1 節。
> **v2.3 追加確認**：課程類型改掛**場次層級**（同一課程各堂可為不同類型）；課程一覽表採 Tab 分頁與排序規則；「意向調查中」課程暫定僅認證學生可見。見 4.4、4.5。
> 原始背景資料見 `KiriFitness課程招生與課程預訂流程.txt`。若本文件與原始 txt 衝突，**以本文件為準**（衝突點見第 16 節）。

## 1. 背景與目標

目前招生完全靠 LINE 群組的記事本留言登記，所有人數統計、成班判斷、場地協調、收費對帳都是手動進行。

痛點不是「流程不好」——現行流程人性化且彈性，這是優點，要保留。痛點有兩個：**全部靠人腦與手工計算**，以及**LINE 群組是封閉的，無法承接新學生**。

### 1.1 專案目標

1. **統一入口**：一個網址，能同時看到「已確認開課」與「正在售票」的場次。
2. **自動化計算**：人數、成班判定、空位、應付金額、場租成本與實拿金額，全部由系統算。
3. **消除「公開」與「收費」之間的空窗**：課程上架的當下就是開賣，不再有「先公布、再催繳」的兩段式動作。這是目前最大的營運風險來源，見第 2.2 節。
4. **作為對外招生工具**：讓有興趣但尚未決定的潛在學生，透過看到「有開什麼課／哪幾天確認有上課／還有無空位／可以怎麼加入」而降低決策門檻，直接下單。**這是 v2 新增的核心目標**，它改變了權限設計，見第 12.1 節與第 13 節。
5. **保留彈性與決策權**：管理員隨時可改期；「少賺也開課」的判斷權留在教練手上，系統不得阻擋。
6. **保留篩選權**：課表可被公開瀏覽，但期票優惠與時段話語權僅限已認證學生。

### 1.2 非目標（v1 不做）

- 線上金流（藍新信用卡）—— 延後至 v2 迭代
- 一對一 / 一對二私人課程預約 —— 延後
- 「找人代上」的名額轉移功能 —— 由學生私下處理，系統不介入
- 任何 LINE 相關服務（LINE Login / LIFF / 官方帳號推播）—— 明確排除，見第 12.2 節

## 2. 核心概念：電影場次 + 當月點數

### 2.1 比喻

把每個月的課程想成「這個月上映的電影」：

- **場次** = 電影的某一個放映時段（某場地、某日期、某時間）
- **一期 N 堂**（目標 4 堂）= 一部電影有幾集，你可以只看一集，也可以全看
- **期票** = 回數券，優惠價，但要在早鳥期買
- **單次票** = 單場入場券，原價
- **早鳥期** = 預售期
- **空位** = 剩餘座位

比喻的價值是把「課程」變成可定價、可銷售、有庫存概念的商品，而「買票」對學生的心理承諾遠強於「登記」。

**但比喻有三處會失效，設計時不可被誤導：**

| 電影 | 本系統 | 影響 |
|---|---|---|
| 只賣兩張票也照放（場地成本已沉沒） | 場租是變動成本，人不夠不能開 | 場次有取消風險，這是電影沒有的問題 |
| 票不記名、可轉讓 | 票必須記名（399 終身限一次、補課年度額度） | 所有票券綁定學生帳號 |
| 場次時間絕不變動 | 管理員需保有隨時改期的權限 | 必須用點數制解決，見 2.3 |

### 2.2 為什麼付款要提前

v1 的設計是「登記時不定價，成班定案後才結算」。這留下一個致命空窗：

> 學生登記（不痛，所以反悔也不痛）→ 人數達標 → **教練依此向場地訂場** → 公布名單 → 要求繳費 → **此時有人反悔**

場地已經訂了，人卻掉了。教練必須自行吸收場租或硬開一堂賠錢的課。

**根本原因不是「收得太晚」，而是「公開」與「收費」之間有時間差。** 因此 v2 的解法是把兩者合併：**課程上架即開賣**，學生看到課表的當下就是買票的當下，空窗期消失。

### 2.3 為什麼是點數，而不是指定場次的票

管理員需要在課程已上架、甚至已售票後仍能更改場次日期（例：老生反映該月週日都沒空，平移到週六早上）。

如果學生買的是「10/12 週日 11:10 那一場的票」，改期就是**違約**——他買的是那個時間的商品，你只能求他同意或退票。

因此學生購買的一律是**當月點數**，而非特定場次的座位。點數與場次解綁後：

- 改期 → 通知已預約者 → 不能配合者退回點數、改約其他場次。**不涉及違約。**
- 場次取消 → 點數自動退回，不需退錢。**「期票有場次沒開」的退費難題從根本消失。**
- 錢在早鳥期就已收到，教練的現金流與人數判斷都建立在真實付款上。

### 2.4 唯一的貨幣：點數

**系統中所有購票行為都轉換為點數，不存在「綁定場次的票」。**

| 購買方案 | 單價 | 點數 | 購買資格 |
|---|---|---|---|
| 期票 | 500 元 / 點 | **該期場次數（可變，目標 4 點 / 2000 元）** | 早鳥期內，**限認證學生（＝舊生）** |
| 單次票 | 600 元 / 點 | 1 點 | 任何時候（含成班後插班） |
| 新生體驗票 | 399 元 / 點 | 1 點 | **終身限一次**，須為從未上過課者 |

**一期的堂數是可變的，由管理員每期設定，不寫死為 4。** 「一期四堂」是教練給自己的開課目標，不是系統規則。實際堂數取決於該場地當月上架幾個場次（月份有幾個週一、教練該月想開幾堂），因此期票點數＝該期上架的場次總數。

流程一律是：**買點數 → 用點數預約場次**。預約不再產生費用。

這個統一讓場次取消、改期、插班、補課全部收斂成同一套邏輯，是本設計最重要的簡化。

## 3. 五階段營運流程

系統並非接手全部流程。以下標明各階段由誰負責。

### 階段 0：時段意向調查 —— 系統負責

取代現行「LINE 記事本留言 + 人工計數」。

- 管理員放上候選時段（含替代方案，例如「週日 11:10」或「改週六 10:00？」）
- 已認證學生對每個候選場次表態「可以 / 不行」
- 有截止時間
- **不收費、不構成購票承諾**，純粹用於喬時間
- 管理員可一眼看到每個時段有幾人、哪些人能來

> 因為公館週一、中和週日是固定時段，多數月份此階段的結論就是「照舊」。此功能的真正用途是**偵測異常**——抓出「這個月大家週日都不行」的情況。

### 階段 1：向場地預訂 —— 線下，系統僅記錄

管理員與工作室的溝通不在系統內。但系統需記錄每個場次的：

- 場地確認狀態（待確認 / 已確認）
- 場租金額（供成本試算使用）

**風險歸屬**：依現行做法，場地是在售票前就訂下的，因此**場租風險由教練承擔**。若意向調查表態可以的人後來沒買票，場地已訂。此風險經評估後接受，理由是老生（固定上課兩年以上）意向可靠度高，且「訂不到場地」的後果比「吃掉一次場租」嚴重得多。

### 階段 2：上架 + 早鳥售票 —— 系統負責

場地確認後，將課程（含其全部場次）上架並同步開賣。

- **早鳥期的起訖日由管理員自行設定，系統不自動計算。** 教練習慣提前至少兩週上架，但這是營運習慣而非系統規則——系統只提供日期欄位，不驗證、不推算、不強制最短天數
- 早鳥期內可買期票（優惠價）與單次票
- **上架即開賣**，不存在「已公開但未開賣」的狀態

### 階段 3：早鳥截止 → 判定成班 —— 系統負責

- 達最少人數的場次 → **已成班**，場地正式確認
- 未達標的場次 → **候補中**（不刪除，見第 8.2 節）

### 階段 4：候補期 + 持續售票 —— 系統負責

日期未過且有空位的場次持續開放購票。候補中的場次一旦達標即自動轉為已成班。

### 階段 5：上課、補課、月底結算 —— 系統負責

月底計算剩餘點數並依責任歸屬處理，見第 10.4 節。

### 3.1 LINE 群組的新角色

從「登記工具」降級為**公告管道**。管理員照舊在群組貼「10 月課表上了，去點一下你哪天能來」，但實際登記、計算、收費都在系統內完成。此決策與第 12.3 節的 Email 觸及率緩解措施一致。

## 4. 名詞定義

| 名詞 | 定義 |
|---|---|
| 場地 | 實體租借地點（公館 Chill 野 wild、中和景安 Afterwork） |
| **課程**（＝一期＝一部電影） | **學生瀏覽與購買的主體。** 一次上架的一組場次，含名稱與票種設定。堂數可變，由管理員每期決定 |
| 場次 | 課程底下某個具體日期時段的一堂課，是**預約與成班**的最小單位。**每個場次各自帶一個課程類型** |
| 課程類型 | TRX 懸吊 / 綜合肌力 / 瑜伽 / 其他。**屬於場次層級，非課程層級**，見 4.4 |
| 意向調查 | 階段 0 的時段表態，不收費、不構成購票 |
| 點數 | 系統唯一貨幣。購票即取得點數，**僅限當月有效** |
| 預約 | 以 1 點換取某場次的一個座位，不產生費用 |
| 早鳥期 | 課程上架到成班判定之間的售票期，期票僅此期間可買。**起訖日由管理員自訂** |
| 候補中 | 早鳥截止未達標但尚未取消的場次，持續售票 |
| 成班人數 | 判斷是否開課的人數，**僅計已付費預約者** |
| 佔位人數 | 判斷是否還有空位的人數，**計入所有實際到場者** |
| 認證學生（＝舊生） | 已上過課、由管理員認證的學生。**「認證學生」與「舊生」為同一概念，系統以單一狀態表示**。享期票購買、意向調查與跨月補課資格 |

### 4.1 兩層結構：課程 / 場次

**「課程」是學生瀏覽與購買的主體，「場次」是課程底下的內容。** 票種掛在課程層級，預約與成班發生在場次層級。

```
課程「10月 公館 全方位訓練營」（一期 4 堂）
├─ 票種設定 ← 學生在這一層購買
│   ├─ 期票 4 點 / 2000 元（僅早鳥期顯示）
│   ├─ 單次票 1 點 / 600 元
│   └─ 新生體驗票 1 點 / 399 元
└─ 場次清單 ← 學生用點數在這一層預約
    ├─ 場次 1：10/06 (一) 20:30　TRX 懸吊　　已成班　3/10 人
    ├─ 場次 2：10/13 (一) 20:30　TRX 懸吊　　已成班　4/10 人
    ├─ 場次 3：10/20 (一) 20:30　綜合肌力　　候補中　2/10 人
    └─ 場次 4：10/27 (一) 20:30　瑜伽　　　　候補中　2/10 人
```

### 4.2 學生的瀏覽動線

1. **課程一覽表** —— 看到「目前有哪些課程」
2. **點進有興趣的課程** —— 此時才列出該課程的**票種**與**場次清單**
3. 購票取得點數 → 用點數預約想去的場次

### 4.3 票種顯示規則

票種清單依該課程**當下是否在早鳥期**決定：

| 課程狀態 | 顯示的票種 |
|---|---|
| 早鳥售票中 | **期票**（標明本期幾堂、總價）＋ 單次票 |
| 已開課（早鳥期已結束） | **僅單次票**——不論底下場次是「已成班」或「候補中」 |

> 期票的總價每期不同（3 堂 1500、4 堂 2000、5 堂 2500），因此**畫面必須明確標示「本期共 N 堂、總計 X 元」**，不可讓學生誤以為期票固定 2000 元。

> **新生體驗票的顯示時機尚未確認**，見第 17 節待決事項。

### 4.4 課程類型屬於場次層級

**同一課程底下的各堂可以是不同類型。** 雖不常發生，但屬於刻意安排的產品——例如「全方位訓練營」可能兩堂 TRX、兩堂其他類型。

因此：

- **課程層**只有名稱／主題（自由文字，例：「10 月 公館 全方位訓練營」、「10 月 中和 週日班」）
- **場次層**各自帶一個課程類型欄位（TRX 懸吊 / 綜合肌力 / 瑜伽 / 其他）
- 課程頁應顯示類型組成摘要（例：「本期包含 TRX × 2、綜合肌力 × 1、瑜伽 × 1」）

**附帶好處**：買單次票的學生（尤其新生）常常只想上特定類型。把類型標在每個場次上，他就能直接挑「我要上瑜伽那堂」，而不是買了才發現內容不對。這對第 13 節的招生轉換是正向的。

### 4.5 課程一覽表：分類與排序

以 Tab 分頁或可篩選分類呈現：

| 分頁 | 內容 | 是否預設 |
|---|---|---|
| 進行中 | 課程狀態為「意向調查中」、「早鳥售票中」、「已開課」 | **預設顯示** |
| 已結束 | 課程狀態為「已結束」 | — |
| 全部課程 | 全部 | — |

**排序規則**：先依狀態（上線中 → 已結束），同組內依時間**由新到舊**。

**可見性**：「意向調查中」的課程**僅認證學生可見**（暫定，見第 17 節）。未登入者與一般使用者在「進行中」分頁只看到「早鳥售票中」與「已開課」的課程。

> 保留「已結束」分頁對招生有價值——從社群媒體來的陌生人看到過去幾個月都有開課紀錄，比只看到當月一兩門課更能建立「這位教練確實一直在開班」的信任感。

### 5.2 中和景安 Afterwork — 公開課

| 項目 | 值 |
|---|---|
| 固定時段 | 週日 11:10–12:10 |
| 場租 | 800 元 / 小時（全區：灰墊 + 黑墊） |
| 最少成班人數 | 2 人 |

**重要決策：中和公開課一律租用全區，即使人數少到只需小區也不降級。**

理由是刻意保留空位給當月補課生與潛在新生。這犧牲了每堂最多 300 元的成本節省，換取「隨時容納得下人」的彈性。

> 這是商業決策，不是疏漏。未來若有人想「優化」成依人數自動選區，必須先推翻此決策。

### 5.3 中和景安 Afterwork — 私人包班（不對外公開）

| 項目 | 值 |
|---|---|
| 固定時段 | 週四 20:00–21:00 |

| 場租（全區：灰墊 + 黑墊） | 800 元 / 小時，上限 7 人 |

私人包班會依實際人數選擇租用區域，超過 3 人必須升級為全區。此為「超過 3 人追加費用」的來源，已反映在第 6.2 節的包班定價中。

## 6. 定價

### 6.1 公開課（見第 2.4 節的點數對照表）

| 方案 | 價格 | 條件 |
|---|---|---|
| 期票 | 500 元 / 點 × 該期場次數（目標 4 點 = 2000 元） | **僅早鳥期可買，且限認證學生（＝舊生）**。須買齊該期全部場次數 |
| 單次票 | 600 元 / 點 | 無限制，隨時可買 |
| 新生體驗票 | 399 元 / 點 | **終身限一次**，須為從未上過課的全新學員 |

> **推論待確認**：期票的優惠是給「全期承諾」的回饋，因此假設學生**必須買齊該期全部場次數**才適用 500 元單價，不可只買其中幾點。若允許部分購買，期票與單次票的界線會消失。

**點數不分場地**：公館買的點可用於中和的場次，反之亦然。成本試算時，一點一律以其購買單價計入該次預約所屬場次的收入。

### 6.2 私人包班（週四，不對外公開）

| 人數 | 總價 | 每人 | 租用區域 | 場租 | 實拿 |
|---|---|---|---|---|---|
| 2 人 | 1400 | 700 | 小區 | 500 | 900 |
| 3 人 | 1650 | 550 | 小區 | 500 | 1150 |
| 4 人 | 2200 | 550 | 全區 | 800 | 1400 |
| 5 人以上 | 每人 500 | 500 | 全區 | 800 | 人數 × 500 − 800 |

## 7. 成班判定

### 7.1 規則

**成班門檻由各場地自訂最少人數決定**（公館 3 人、中和 2 人）。

### 7.2 「淨收 800」的定位

原始文件寫「扣除成本後鐘點費至少要有 800 以上才上課」。**此條不是硬性門檻，而是僅供教練參考的顯示數值。**

原因是兩者在數學上算不起來：

| 情境 | 收入 | 場租 | 實拿 | 是否達 800 |
|---|---|---|---|---|
| 公館 3 人，全單次票 | 1800 | 900 | 900 | 達標 |
| 公館 3 人，全期票 | 1500 | 900 | **600** | 未達 |
| 中和 2 人，全單次票 | 1200 | 800 | **400** | 未達 |
| 中和 2 人，全期票 | 1000 | 800 | **200** | 未達 |
| 中和 3 人，全單次票 | 1800 | 800 | 1000 | 達標 |
| 中和 4 人，全期票 | 2000 | 800 | 1200 | 達標 |

教練已明確表示「少賺也得開課」是**必要且刻意的妥協**，理由有三：

1. 維持「我一直有在開班」的品牌印象
2. 保留當月補課生的去處
3. 保留新生隨時能加入的機會

### 7.3 系統該做的事

- **不得**因實拿金額低於 800 而阻擋成班
- **必須**在管理畫面即時顯示每個場次的預估收入、場租成本與實拿金額，讓教練自行判斷
- 私人包班需額外顯示「以目前人數，租小區 vs 全區的成本與實拿對照」

## 8. 課程與場次生命週期

### 8.1 兩層狀態機

因為採兩層結構（第 4.1 節），狀態機也是兩層：**課程狀態決定「賣什麼票」，場次狀態決定「哪天真的有課」。**

#### 課程狀態（決定票種）

| 狀態 | 說明 | 學生可做的事 |
|---|---|---|
| 草稿 | 管理員建立中，尚未發布 | 看不到 |
| 意向調查中 | 時段未定，收集老生表態 | 認證學生可表態「可以 / 不行」 |
| 早鳥售票中 | 時段已定、場地已確認 | **買期票或單次票**、用點數預約場次 |
| 已開課 | 早鳥期結束，課程進行中 | **僅能買單次票**、用點數預約尚有空位的場次 |
| 已結束 | 全部場次結束 | 僅供查閱 |

#### 場次狀態（決定是否上課）

| 狀態 | 說明 | 學生可做的事 |
|---|---|---|
| 售票中 | 尚未進行成班判定 | 用點數預約 |
| 已成班 | 達最少人數，場地正式確認 | 用點數預約（若有空位）、登記補課 |
| 候補中 | 早鳥截止未達標，持續累積人數 | 用點數預約 |
| 已取消 | 到最後確認日仍未達標，或管理員主動取消 | 點數已全數退回 |
| 已結束 | 該堂已上完 | 僅供查閱 |

> **注意兩層的獨立性**：一個課程可以處於「已開課」，而其底下的場次同時存在「已成班」與「候補中」。這正是第 8.2 節的情境——前兩堂開了，後兩堂還在湊人。

### 8.2 候補中：未達標的場次不要急著刪掉

v1 原設計為「截止後未達標即關閉或刪除」。**這在 v2 太早了。**

實例：10 月公館四個週一，早鳥截止時前兩堂各 3 人達標、後兩堂僅 2 人。但第四堂在 10/27，還有三週——這期間完全可能有人買單次票補上第三人。

因此未達標場次進入**候補中**：繼續公開售票、繼續累積人數，達標即自動轉為已成班並通知所有已預約者；直到該場次自己的**最後確認日**才真正取消。

兩個好處：救回原本會流掉的課；已買期票的人看到「這堂還在湊人」，感受遠優於看到「已取消」。

> **最後確認日由管理員逐場次自行設定**，系統不自動推算。管理員最清楚各場地要求多久前確認，也可能因場次而異。未設定時預設不自動取消，由管理員手動處理。

### 8.3 關鍵轉換規則

- **期票僅在課程處於「早鳥售票中」時可購買。** 課程一旦進入「已開課」，票種清單只剩單次票。這是**課程層級**的規則，與個別場次是否成班無關。
- **插班（成班後加入）適用單次票 600 元**；若為從未上過課的全新學員，可用 399 體驗票（終身一次）。
- 插班不得補買期票。期票優惠是給「願意在不確定時就先付錢」的學生的回饋。

## 9. 場次變更與取消

### 9.1 管理員的改期權限

**管理員有權在課程已上架、場次甚至已被預約後，更改場次的日期與時段。** 這是明確的需求，不是例外處理。

實務上管理員在更改前一定會先與老生確認，但**系統不得以任何形式阻擋此操作**。

點數制（第 2.3 節）使此權限安全：學生持有的是點數而非特定座位，改期不構成違約。

### 9.2 改期時系統必須做的事

1. 通知所有已預約該場次的學生（Email）
2. 提供每位已預約者兩個選擇：**維持預約** 或 **取消預約並退回點數**
3. **重新判定成班狀態** —— 若退點導致人數掉到門檻以下，該場次須退回「候補中」，並提醒管理員
4. 保留變更歷史紀錄（日期、原因、影響人數），以備爭議查核

### 9.3 場次取消時

- 所有已預約者的點數**全數自動退回**
- 通知所有已預約者
- 退回的點數可用於當月任何其他場次
- **不涉及退錢**（除非月底仍無處可用，見第 10.4 節）

## 10. 售票、點數與結算

### 10.1 核心原則：上架即開賣，買點不買座位

付款發生在購票當下（早鳥期或之後任何時間）。購票取得點數，預約場次不再產生費用。

### 10.2 點數規則

| 項目 | 規則 |
|---|---|
| 效期 | **僅限當月** |
| 使用範圍 | **可跨場地**（公館買的點可用在中和） |
| 跨月結轉 | **不可** |
| 退回時機 | 場次取消、場次改期後學生選擇退約 |

> **嚴守當月制的理由不只是政策一致性。** 若允許跨月結轉，預收款會累積成實質儲值，可能觸及預付型交易的相關規範。維持當月、小額、單期，可將此風險降到最低。

### 10.3 人數計算：兩個不同的數字

同一場次的出席者有三種身分，對「成班」與「空位」的影響不同：

| 身分 | 是否扣點 | 計入成班人數 | 計入佔位人數 |
|---|---|---|---|
| 已付費預約者（期票 / 單次票 / 體驗票） | 是 | **是** | 是 |
| 當月補課者 | **否** | **否** | **是** |
| 找人代上的替代者 | 否（系統不處理） | 否 | 是 |

- **成班人數 = 已扣點的預約者。** 若把補課者算進去，2 個補課生會讓場次誤判成班，結果教練穩賠場租。
- **剩餘空位 = 人數上限 − 佔位人數。** 補課者不扣點但確實佔一個位子，插班判斷必須扣掉他們。
- 補課登記**只在場次確認成班後開放**，因此補課永遠不會干擾成班計算。

### 10.4 月底剩餘點數：依責任歸屬處理

點數制把所有難題收斂到這一個決策點上。判斷標準是**「這一點用不掉，是誰的責任」**：

| 情境 | 責任 | 處理 |
|---|---|---|
| 當月開了多堂課，學生自己沒來，剩下點數 | 學生 | **作廢**（或走既有補課機制）。符合現行「不退費」政策 |
| 當月開成的場次總數不足，學生物理上無處可用 | 教練 | **退款**。服務未提供，作廢無正當性 |

這個區分不是新規則。現行的「不退費」一直是針對**學生缺席**，而非**教練沒開課**；預付模式只是把這個一直隱含的區別逼到檯面上。

**實作方式：不要把規則寫死。** 以數十人的規模，系統在月底列出「尚有剩餘點數的學生 + 剩餘原因（被取消幾次預約、當月尚有幾堂可用）」，由管理員逐筆決定退款或作廢。這比猜不準的自動判定可靠，也保留一貫的人性化處理空間。

### 10.5 意向調查與購票的銜接

為避免學生操作兩次，**意向調查中勾選「可以」的場次，於開賣時自動成為該學生的待結帳清單**。學生登入後看到「你先前表示這四場可以，合計 2000 元」，確認付款即完成。

對管理員的附帶價值：可直接比對「表態可以卻未購票」的名單。

### 10.6 繳費方式（v1）

- 銀行轉帳匯款
- LINE Pay Money
- iPass Money

三者皆為手動流程。系統負責：產生應付金額、提供學生回報匯款資訊（如帳號末五碼）的介面、讓管理員標記「已收款並發點」、以及未付款追蹤。

> **注意**：手動付款與「上架即開賣」之間仍有一個縮小版的空窗——學生下單後到管理員確認收款前，點數尚未發出。需決定此期間是否先行保留座位、保留多久，見第 17 節待決事項。串接線上金流可根本解決此問題，為 v2 迭代的主要理由。

## 11. 補課與退費

### 11.1 退費

**學生因自身因素不能出席時不退費**，可自行找人代上。

代上者**不視為新生**（不得使用 399 體驗票），名額轉移由原學生私下處理，系統不介入、僅需知道該位子已被佔用。

**但「教練未開成課」不屬於此範圍**，適用第 10.4 節的退款規則。

### 11.2 補課規則

| 類型 | 條件 | 費用 |
|---|---|---|
| 當月補課 | 當月另一場次已成班且有空位 | 免費，不扣點 |
| 跨月補課（第一次） | **僅認證學生（＝舊生）**，每年度一次，無條件 | 免費 |
| 跨月補課（第二次） | 僅認證學生，同年度第二次 | 300 元 |
| 跨月補課（第三次起） | 該年度不再提供 | — |

### 11.3 系統必須追蹤的跨時間狀態

以下規則綁定在「人」身上且跨時間累積，**因此必須有學生帳號與歷史紀錄**，無法靠匿名購票實作：

- 新生體驗 399 元是否已使用（終身一次）
- 該年度跨月補課已使用次數
- **認證學生（＝舊生）身分**——單一狀態，同時決定期票購買資格、意向調查資格與跨月補課資格

## 12. 帳號、權限與通知

### 12.1 分層權限（待確認）

v1 原設計為「登記需經邀請碼或教練核准」。**這與第 1.1 節新增的招生目標直接衝突**——一個看了課表、動心想試一次的陌生人，若還要等核准，多半會流失。核准機制正好卡在轉換漏斗的最後一步。

解法是分層，而非二選一：

| 行為 | 需要什麼 | 理由 |
|---|---|---|
| 瀏覽課程一覽、場次、空位 | 不需登入 | 招生漏斗的入口，摩擦為零 |
| 瀏覽「意向調查中」的課程 | **限認證學生（＝舊生）** | 時段未定的課程不對外曝光（暫定，見 4.5） |
| 買單次票 / 新生體驗票 | 註冊 + 付款，**不需核准** | 招新入口，摩擦必須最低；教練同時賺到錢 |
| 買期票（優惠價） | **限認證學生（＝舊生）** | 優惠價保留給長期承諾者 |
| 參與意向調查 | **限認證學生（＝舊生）** | 喬時間的話語權保留給固定班底 |

**認證學生是系統中唯一的學生分級。** 它同時決定三件事：期票購買資格、意向調查資格、跨月補課資格。不另設「舊生」等其他身分。

**這個設計就是現行做法的數位化。** 現行是「在工作室合作課或代課時遇到，上過我的課、有意繼續的才邀進 LINE 群組」。新設計中，「上過我的課」可以發生在自己的系統內——陌生人用 399 體驗票上一次，教練當場觀察，適合的升級為認證學生並給予期票資格。

**效果是招生來源從「別人的場子」擴大到「自己的網站」，而篩選權完全沒有讓出。**

### 12.2 登入方式：Email 魔法連結

**明確排除所有 LINE 相關服務**，包含 LINE Login。系統與 LINE 完全無關。

| 項目 | 決策 |
|---|---|
| 登入方式 | Email 魔法連結（點信中連結即登入，不設密碼） |
| 實作方式 | 使用託管驗證服務（Supabase Auth / Clerk / Firebase Auth 等），**不自行實作密碼與 session 管理** |
| 成本 | 以現有規模（數十人）落在免費額度內 |
| 手機簡訊 OTP | v1 不做（每則簡訊需付費、需另申請簡訊商） |

### 12.3 全 Email 路線的風險與緩解

**風險**：學生族群全部習慣在 LINE 上溝通，部分人可能不常查看 Email，導致「場次改期」「該付款了」等通知漏接。

三項必要緩解措施：

1. **長效期登入狀態（建議 90 天）** —— 讓「去收信」一季只發生一次，把登入摩擦降為一次性。
2. **Email 送達率必須認真處理** —— 需自有網域並正確設定 SPF / DKIM / DMARC，透過正規交易信服務寄送（Resend / Postmark / AWS SES）。魔法連結若進垃圾信匣，學生將完全無法登入，系統即失效。此項**不可省略**。
3. **LINE 群組繼續作為公告管道** —— 見第 3.1 節。

### 12.4 通知觸發時機

- 意向調查開始 / 即將截止
- 新課程上架開賣
- **場次日期或時段變更**（發給已預約者，含維持／退約的選擇連結）
- 場次成班 / 轉候補 / 取消
- 早鳥期即將結束
- 付款確認與點數發放
- 未付款提醒
- 月底剩餘點數通知

### 12.5 名單可見性

現行做法會在 LINE 群組公開「哪一天是哪些學生」以保持透明，因為老生互相熟識。系統可直接數位化此做法，且無需手動整理貼文。

但需分級，**從社群媒體導流進來的陌生人不應看到學生姓名**：

| 對象 | 可見內容 |
|---|---|
| 未登入者 | 僅人數與剩餘空位（「已 3 人，剩 7 位」） |
| 已登入學生 | 完整預約名單 |

## 13. 招生漏斗

第 1.1 節第 4 點要求系統能承接社群媒體導流。要讓陌生人能下單，光有課表不夠——他看到「公館週一 20:30」不會知道那是什麼課。

v1 至少需要：

- **課程類型說明**：TRX 懸吊、綜合肌力、瑜伽各是什麼、適合誰、需要什麼程度、要帶什麼
- **場地資訊**：地址、交通方式、現場設備（更衣室、淋浴等）
- **新生體驗票 399 元的明顯入口** —— 這是主要的獲客優惠，不該藏在流程深處
- **加入方式說明**：現在可以怎麼加入（買單次票 / 體驗票），以及認證學生能多享有什麼

> **已知風險**：新生體驗票不需核准即可購買，理論上可用不同 Email 重複使用。但金額小、規模小，建議以購票時填寫姓名與手機供人工比對即可，不做過度防範。

## 14. v1 功能範圍

### 14.1 包含

- 時段意向調查（階段 0）
- 課程一覽表（Tab 分頁與排序）與課程頁（票種清單 + 場次清單 + 類型組成摘要），見 4.1–4.5
- 場次層級的課程類型標記（TRX 懸吊 / 綜合肌力 / 瑜伽 / 其他）
- 課程上架與售票（期票 / 單次票 / 新生體驗票），票種依早鳥期自動切換
- 點數發放、預約、退回與當月效期管理
- **管理員改期與取消，含通知、退約選擇、成班重新判定**
- 成班判定、候補中狀態、最後確認日自動取消
- 成班後的付費插班（依剩餘空位）
- 私人包班（隱藏課程，不對外公開）
- 補課額度追蹤（當月補課、跨月年度額度、第二次 300 元）
- 手動匯款 / LINE Pay / iPass 的回報與對帳
- 場租成本與收支試算（每場次預估收入、成本、實拿）
- 月底剩餘點數清單與逐筆退款 / 作廢處理
- 學生帳號（Email 魔法連結）與認證學生分層權限
- 招生漏斗頁面（課程說明、場地資訊、體驗票入口）
- Email 自動通知

### 14.2 不包含

- 線上金流（藍新信用卡）
- 一對一 / 一對二預約
- 名額轉移（找人代上）功能
- 任何 LINE 整合
- 點數跨月結轉

## 15. v1 → v2 的差異

| # | v1 | v2 | 理由 |
|---|---|---|---|
| 1 | 登記時不定價，成班後結算收費 | **上架即開賣，購票取得點數** | 消除「公開」與「收費」間的空窗，見 2.2 |
| 2 | 期課 = 某場地 4 堂的登記 | **期票 = 當月 N 點（N 由管理員每期設定），不綁場次** | 使改期不構成違約，並消除「期課未開滿」的退費難題，見 2.3 |
| 3 | 期課未開滿時，學生選擇改用單堂價結算或挪用堂票 | **場次取消即自動退點**，月底再依責任歸屬處理 | 原設計讓學生為「教練沒開成班」多付每堂 100 元，道義上站不住腳 |
| 4 | 招生期間可調整時段，成班後不可 | **管理員隨時可改期**，含已售票後 | 明確需求，見 9.1 |
| 5 | 未達標場次「關閉或刪除」 | **進入候補中，持續售票至最後確認日** | 救回原本會流掉的課，見 8.2 |
| 6 | 登記一律需邀請碼或核准 | **分層**：單次票 / 體驗票免核准，期票與意向調查限認證學生 | 原設計與新增的招生目標衝突，見 12.1 |
| 7 | 「一律不退費」 | 區分**學生缺席（不退）**與**教練未開課（退款）** | 預付模式逼出此區別，見 10.4、11.1 |
| 8 | 系統自「招生登記」開始接手 | **往前吃一步，接手時段意向調查** | 人工計數是主要痛點所在，見階段 0 |
| 9 | 目標未含對外招生 | **新增「作為對外招生工具」為核心目標** | 見 1.1 第 4 點、第 13 節 |

### 17.1.1 已於 2026-09-12 解決

| 原項目 | 結論 |
|---|---|
| 一期堂數是否固定為 4 | **可變**，由管理員每期設定。「一期四堂」是教練的開課目標，非系統規則 |
